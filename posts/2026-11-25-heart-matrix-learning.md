## 1. 五根线，为什么能控制 256 颗灯？

8×32 点阵由四片 8×8 模块组成，每片背后是一颗 MAX7219。它负责保存显示数据、扫描 LED、调节亮度。Arduino 负责告诉它“哪些灯亮”和“有多亮”。

| 接线 | UNO R3 引脚 | 通俗解释 |
| --- | --- | --- |
| VCC | 5V | 按模块规格供电 |
| GND | GND | 共地，作为信号的参考 |
| DIN | D11 | 数据一位一位进入 |
| CLK | D13 | 告诉芯片什么时候读取数据 |
| CS / LOAD | D10 | 拉低传输，拉高锁存这一组数据 |

项目使用 Arduino 内置 SPI 库，不额外安装第三方点阵库。改线前断电，核对模块电压、极性和引脚。

## 2. 寄存器：给芯片的小格子写内容

每条指令有两个字节：一个说明写到哪里，一个说明写什么。

| 地址 | 在项目中的用途 |
| --- | --- |
| 0x0C | 显示开关 |
| 0x0A | 亮度，取值 0–15 |
| 0x0B | 扫描范围，写 7 表示使用八条扫描线 |
| 0x09 | 关闭数字译码，使用点阵模式 |
| 0x0F | 关闭显示测试模式 |
| 0x01–0x08 | 八组显示数据，物理方向取决于模块接线 |

`maxSetup()` 就是在给各片芯片设置这些参数。

## 3. 四片级联：像一条传送带

先发送的数据会向更远的芯片移动。本项目每次拉低 CS 后发送四组“地址 + 数据”，最后拉高 CS；目标芯片得到有效指令，其余芯片得到空操作。

```cpp
for (int8_t i = CHIPS - 1; i >= 0; i--) {
  if (i == chip) { SPI.transfer(reg); SPI.transfer(value); }
  else { SPI.transfer(0x00); SPI.transfer(0x00); }
}
```

这里每次都发送四组，不是“写第几片就只发送几组”。芯片顺序和整幅图像的左右方向要分别核对。

## 4. 一个字节，存八颗灯

`canvas[32]` 是软件画布：一列一个字节，每一位代表该列的一颗灯。32 列只需要 32 字节。

```cpp
canvas[x] |= (1 << y);      // 把第 y 位设为 1
canvas[x] &= ~(1 << y);     // 把第 y 位设为 0
if (canvas[x] & (1 << y))   // 判断这一位是否为 1
```

字符画里的 `art[y][x]` 是“第 y 行、第 x 列”。`drawHeart()` 把字符 `#` 转成画布中对应的位。

## 5. 画布和模块的坐标要对上

软件按列存储，并不意味着模块也按列解释数据。原项目最终通过 `show()` 把每一列的位重新组成一行，再发送给对应的显示寄存器。

```cpp
for (uint8_t r = 0; r < 8; r++) {
  uint8_t bits = 0;
  for (uint8_t b = 0; b < 8; b++) {
    if (canvas[c * 8 + b] & (1 << r)) bits |= (1 << b);
  }
  maxWrite(c, r + 1, bits);
}
```

这段是核心映射示意；完整源码还包含方向开关。**转置是行列互换，不等同于旋转 90°。** 也不能仅凭亮斑外形断定某一种映射错误。

## 6. 爱心没换形状，变的是亮度

字符画只在 `setup()` 中写入一次。之后用 `millis() % 1100` 计算当前处于心跳周期的哪一段。

| 时间段 | 当前代码的亮度变化 |
| --- | --- |
| 0–220 ms | 从 15 向 7 回落，“咚” |
| 220–340 ms | 保持 7，短暂停顿 |
| 340–560 ms | 从 12 向 6 回落，“哒” |
| 560–1100 ms | 保持 5，安静但仍可见 |

原笔记使用了“非阻塞的雏形”这个说法。准确地说，程序已经用时间计算动画阶段，但 `loop()` 里仍有 `delay(15)`，并不是完全非阻塞。

## 7. 把程序看成五件小事

```text
setup()：初始化 SPI → 配置 MAX7219 → 全亮自检 → 写入爱心
loop() ：计算当前阶段 → 设置亮度并刷新显示 → 等待 15 ms
```

全亮自检用于初步检查显示链路。核对行列映射时，选择位置已知、转置后会发生变化的标记；主对角线本身对称，不能单独用它排除转置问题。
