# 这个网站是怎样一点点长出来的

下面把“为什么改”和“改成了什么”放在一起。早期过程根据对话和 `notes/` 记录整理；提交表根据本机 Git 历史核对。不推测每一步花了多少小时，也不把示例实验写成你已经完成的成果。

## 从愿望到结构

| 阶段 | 当时的需求或问题 | 采用的做法 | 可以学到什么 |
| --- | --- | --- | --- |
| 最初骨架 | 想把嵌入式、英语与个人表达放在一起 | 先划分内容，再决定页面 | 先明确用途，再设计装饰 |
| 双空间 | 工业工作室与温暖沙龙气质不同 | 页面分别装修，品牌和入口保持关联 | 协调不等于所有页面用同一种颜色 |
| V0.6 | 不只展示，还要 AI 对话和项目文章 | 增加 Node 服务、DeepSeek 接口、Markdown 博客 | 静态展示与动态服务有不同工作量 |
| Spark 精简版 | 首页繁琐，学习功能有些暂时用不上 | 改名、删减入口、收藏与文章分离 | 适合自己的功能比数量更重要 |
| 星球尝试 | 玩具球和点阵球不符合你的审美 | 从 CSS 球体到可拖动球面，再改地球贴图 | 先让交互成立，再修正视觉 |
| 工作台重做 | 全是相似卡片，资料缺少层次 | 工作室主图、项目展示、资料目录、日志入口 | 图片、留白、内容层次共同决定观感 |
| 最新版本 | 还需要更易读的代码和英语复盘 | 增加代码预览、练习报告、光弧留言 | 功能需要说明真实边界，不能只像真的 |
| 本次交接 | 网站暂时告一段落，想学会怎么做 | 整理本手册、学习路线和内容模板 | 做完之后的复盘也是开发的一部分 |

## 哪些旧记录需要带着版本看

`notes/` 是历史记录，不应删除。但以下内容已经变化：

- 早期课程、进度工具并非当前嵌入式页的主要界面。
- 早期“首页三个入口”已经变成两个；博客从嵌入式进入。
- 星球不再只是点阵，也不再保留之前的蓝色光晕；当前代码加载地球贴图。`planet.js` 顶部旧注释写着“不用贴图”，与后面的实际加载代码已不完全一致。
- 旧说明把浏览器本地存储和文章文件一起称为“数据库”，只是粗略比喻。当前公共留言数据库是 Supabase；这三种存储不能互相替代。
- 旧说明中若把 Render 的博客写入说成可公开使用，以 `blog-api.mjs` 为准：线上直接写入被限制。
- 本对话里曾有一次同步 GitHub 被审批额度中断；后续提交已经出现在当前仓库记录中。因此不能把那一次失败继续当成最新发布结论。

## 已做过的检查，与本次的检查范围

前几轮有桌面 / 手机预览、星球交互、资源请求和接口模拟测试记录。这些记录针对当时的版本，不应扩大成“最新一切功能都完整验收”。

本次是文档工作：核对代码、入口、配置样本、数据文件和提交记录；检查文档链接及示例。没有重新调用付费模型，没有发真实留言，没有读取 `.env` 的真实密钥，也没有进行硬件实验。

仓库现有的 `tests/chat-api.test.mjs` 与 `tests/guestbook.test.mjs` 覆盖部分接口行为，使用模拟服务。它们不等于真实 DeepSeek、Supabase、手机兼容性或硬件接线都测试过；当前也没有独立的练习报告、博客写入和代码预览测试文件。

## 以后维护时值得记住的几件事

多轮样式表叠加、部分文件一行很长，会让初学者阅读困难。后面可以先格式化，再按页面整理样式，但应一次改一小块并做页面对照。

新增 API 能力时，不仅要画按钮，还要补正常、失败、超时的验证。当前 `package.json` 的语法检查清单尚未包含新加的 `arduino-viewer.js`，检查它时需单独执行 `node --check arduino-viewer.js`。

站点还没有账号系统、跨设备 AI 对话档案、自动资料检索或 Obsidian 双向同步。之后是否添加，取决于你实际写了多少资料、遇到了什么困难。本轮没有实施这些设想。

## 当前阶段的约定

先停止加功能。下一阶段的优先级是：**收集少量好资料 → 写自己的理解 → 做一个小项目 → 留下一篇复盘**。搜索、分类筛选等功能，等内容多到确实难找时再考虑。
