# 学习笔记：从一块点阵开始

> 适合：完全没碰过单片机、只会一点点 C 语言的人。
> 读完你应该能说清楚：这块点阵为什么只用 5 根线就能点亮 256 颗灯。

---

## 1. 先把硬件看明白

你手里这块“8×32 点阵”不是一整块屏，是 **4 片 8×8 拼起来的**：

```
[8×8 #1][8×8 #2][8×8 #3][8×8 #4]      ← 每片 64 颗灯
 └─────── 32 列 × 8 行 = 256 颗 ───────┘
```

每一片背后都有一颗 **MAX7219** 芯片。这颗芯片干三件事：

1. 记住“哪些灯该亮”（存 8 个字节）
2. 不停地扫描这 8 行（每秒几百次，人眼看不到闪烁）
3. 控制亮度（0–15 级）

所以 Arduino 要做的其实只有一件事：**把 8 个字节写进芯片**。剩下的它自己搞定。

---

## 2. 五根线在干什么

| 线 | 全名 | 通俗解释 |
|---|---|---|
| VCC / GND | 电源 | 供电 |
| DIN | Data In | 一位一位地送数据 |
| CLK | Clock | 每敲一下，DIN 上的那一位就被读走 |
| CS | Chip Select | 拉低开始收，拉高“收货确认” |

这就是 **SPI**：一根数据线 + 一根时钟线，**时钟每跳一次传 1 bit**。

一个字节 8 位，所以传一个字节要跳 8 次。传“地址+数据”两个字节，要跳 16 次。

> 关键理解：数据不是“同时”送过去的，是**一位一位排队走**的。这个“排队”的概念，下一节级联会用到。

---

## 3. 寄存器：芯片里的 14 个小格子

MAX7219 内部有一排寄存器，你只要往对应地址写值就行。这个项目只用到 6 个：

| 地址 | 名字 | 写什么 |
|---|---|---|
| 0x0C | 开关 | 1 = 显示，0 = 关闭 |
| 0x0A | 亮度 | 0–15 |
| 0x0B | 扫描行数 | 写 7 = 8 行全用 |
| 0x09 | 译码模式 | 点阵必须写 0（不做数字译码） |
| 0x0F | 测试模式 | 写 0 关闭 |
| **0x01–0x08** | **显示数据** | **这 8 个格子就是“哪些灯亮”** |

初始化那几行代码就是在挨个写这些格子：

```cpp
maxWrite(c, 0x0B, 0x07);   // 8 行全用
maxWrite(c, 0x09, 0x00);   // 不译码
maxWrite(c, 0x0A, 0x03);   // 亮度 3
maxWrite(c, 0x0C, 0x01);   // 开显示
```

---

## 4. 级联：一条链，4 片芯片

4 片芯片是 **串起来** 的：

```
Arduino DIN → [#1 DIN] [#1 DOUT → #2 DIN] [#2 DOUT → #3 DIN] ... → [#4]
```

你发 16 位，第 1 片收下后，会把**原来肚子里的那 16 位从 DOUT 吐出来**给第 2 片——像一条传送带。

所以想给第 3 片写数据，得连着发 3 组：前两组是“空操作”（0x00），第 3 组才是真数据。

代码里就是这么干的：

```cpp
for (int8_t i = CHIPS - 1; i >= 0; i--) {
  if (i == chip) { SPI.transfer(reg); SPI.transfer(value); }
  else           { SPI.transfer(0x00); SPI.transfer(0x00); }  // 空操作，让它把位置让出来
}
```

> 注意循环是**倒着**走的：先发的会走得最远，最后发的留在最近的一片。

---

## 5. 位运算：一个字节管 8 颗灯

一个字节有 8 个 bit，正好管 8 颗灯：

```
bit:  7 6 5 4 3 2 1 0
灯:   ■ □ ■ □ □ ■ □ □
```

三个常用操作，记住就够：

```cpp
canvas[x] |= (1 << y);      // 点亮第 y 颗：把第 y 位置 1
canvas[x] &= ~(1 << y);     // 熄灭第 y 颗：把第 y 位置 0
if (canvas[x] & (1 << y))   // 检查第 y 颗亮不亮
```

`1 << y` 的意思是“把 1 往左推 y 位”：

```
1 << 0 = 00000001
1 << 3 = 00001000
1 << 7 = 10000000
```

> 为什么用位运算而不是 8 个 bool？因为一个字节就能装 8 颗灯，32 列只需要 32 个字节（32 B），省内存又省事。

---

## 6. 画布模型：为什么“一列一个字节”

代码里画布是这样存的：

```cpp
uint8_t canvas[32];   // 32 列，每列 1 个字节，bit0 = 最上面那颗
```

也就是 **canvas[列] 的 8 个 bit = 这一列从上到下的 8 颗灯**。

为什么这么存？因为 MAX7219 的显示寄存器就是这个格式：**一个寄存器 = 一列（或一行）的 8 颗灯**。画布和硬件格式一致，发数据时就不用再算了。

把字符画刷进画布：

```cpp
for (uint8_t y = 0; y < 8; y++)
  for (uint8_t x = 0; x < 32; x++)
    if (art[y][x] == '#') canvas[x] |= (1 << y);
```

`art[y][x]` 是“第 y 行第 x 列”，`canvas[x]` 的第 y 位——正好对上。

---

## 7. 转置：这个项目最大的坑

**大多数** 8×8 模块：寄存器 0x01 = 第 1 **列**。
**这块** 8×32 板：寄存器 0x01 = 第 1 **行**，字节的 8 个 bit 才是 8 列。

差别就是“行列互换”，数学上叫**转置**。

如果按列写、硬件按行读，每一片都会把图像转置一遍。爱心是左右对称的，转置后左右两半各自旋转 90°，看起来就是**两块互不相干的亮斑**。

修法是发数据前自己先转一次（负负得正）：

```cpp
for (uint8_t r = 0; r < 8; r++) {            // 目标：第 r 行
  uint8_t bits = 0;
  for (uint8_t b = 0; b < 8; b++) {          // 目标：第 b 列
    if (canvas[c * 8 + b] & (1 << r)) bits |= (1 << b);
  }
  maxWrite(c, r + 1, bits);
}
```

> 换个角度想：从画布里“按行取 8 个点”，拼成一个字节，发给第 r 个寄存器。

## 8. 时间：为什么不用 delay()

新手最容易写成这样：

```cpp
while (1) {
  show(15); delay(100);
  show(5);  delay(100);
}
```

问题：`delay()` 期间单片机**什么都干不了**，想加个按键、加个传感器就全卡住了。

正确做法是 **millis() 记时间，loop() 自己跑得飞快**：

```cpp
uint16_t t = millis() % BEAT_MS;   // 0 ~ 1100 循环
if (t < 220)      level = 15 - t * 8 / 220;
else if (t < 340) level = 7;
...
```

`millis()` 返回开机以来的毫秒数，`% 1100` 让它每 1100 ms 归零一次。这样主循环一直在跑，随时能插别的事。

> 这就是“非阻塞”的雏形。以后加按键、加传感器，全靠这个思路。

## 9. 亮度：白送的呼吸效果

亮度就是寄存器 0x0A，取值 0–15。每帧改一下，就有了“心跳”：

```
0 ms ──── 15  （咚，最亮）
220 ms ── 7   （回落）
340 ms ── 7   （停一下）
560 ms ── 12  （哒）
1100 ms ─ 5   （安静，但还看得清）
```

**图案一帧都没变，变的只是亮度**——这是这个项目里最省事、效果又最好的一个决定。

## 10. 调试方法：自检图案的学问

好的调试图案要满足两点：**一眼能看懂**、**错了能定位**。

这个项目用过三种：

| 图案 | 能查出什么 | 查不出什么 |
|---|---|---|
| 全亮 1 秒 | 供电、接线、4 片是否都通 | 方向、映射 |
| 四组点（1/2/3/4 个） | 片序（从左到右还是反过来） | 行列方向 |
| L 形（一整行 + 一整列） | 行方向、列方向 | **转置**（重点！） |

最后一行是血的教训：**L 是一条整行 + 一条整列，转置之后长得一模一样**，所以它测不出转置问题。真正暴露问题的是爱心这种“不满行、不满列”的图形。

> 教训：**测试图案本身要能区分你想测的所有情况**。测不出来不等于没问题。

## 11. 代码结构一览

```
setup()  只跑一次
 ├── SPI 初始化（4 MHz，MSB 先出）
 ├── maxSetup()   写 6 个控制寄存器
 ├── selfTest()   全亮 1 秒
 └── drawHeart()  把字符画刷进画布（只刷这一次）

loop()   每秒跑几十次
 ├── 算当前该多亮（millis + if/else）
 └── show(level)  转置后发给 4 片芯片
```

关键设计：**图案只画一次，循环里只改亮度**。这样循环里几乎没有计算，改起来也简单。

---

## 12. 下一步可以学什么

按难度排：

1. **改图案**：只动字符画，理解 `art[y][x]` 和 LED 的对应
2. **加按键**：`digitalRead` + 去抖（第一次接触“状态”）
3. **加传感器**：光敏电阻 + `analogRead`（第一次接触模拟量）
4. **加蜂鸣器**：`tone()`（第一次让项目“出声”）
5. **滚动字幕**：字符串 + 位移（第一次处理“动画数据”）
6. **自己写驱动库**：把 `maxWrite/show` 封装成 class（第一次做抽象）

每一个都只比上一个大一点点。**别一次学两个新东西**——这是我从这个项目里学到的最实用的一条。
