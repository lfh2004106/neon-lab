# 错误指南：灯不对的时候看这里

> 按「现象」查，不用从头读。
> 每条都尽量写清楚：**怎么判断**、**为什么**、**怎么修**。

---

## 0. 先记住排查顺序

出问题不要乱试，按这个顺序，每步只改一个变量：

```
① 电     → 全亮自检能不能过？（不能过 = 电源/接线）
② 通信   → 4 片是不是都亮？（只有几片 = 级联/某片坏）
③ 方向   → 图案是正的还是倒的/反的？（FLIP_X / FLIP_Y）
④ 形状   → 图案对得上吗？（对不上 = 映射/转置问题）
```

**一次只改一个地方**，改完立刻看效果。同时改三个，你不知道是哪个起了作用——这个项目里我在这上面浪费了至少一小时。

---

## 1. 完全不亮

| 现象 | 多半是 | 怎么修 |
|---|---|---|
| 上电全亮自检都没有，一颗都不亮 | 供电没通 | 万用表量点阵 VCC–GND 有没有 5V；换一根 USB 线（很多线只能充电不能传数据） |
| UNO 上的 ON 灯亮，点阵全黑 | DIN/CLK/CS 接错或没插到底 | 拔下来重插，杜邦线插到底会“咔”一下 |
| 电脑“叮”一声但 IDE 找不到端口 | 缺 CH340 驱动 | 设备管理器看有没有黄色感叹号，装套件里的 CH340 驱动 |

> **判断技巧**：把 VCC 和 GND 单独接好，DIN/CLK/CS 全拔掉，上电后点阵应该**全黑**（没有数据就不会亮）。这一步能确认供电是不是好的。

---

## 2. 只有一片 / 一半亮

| 现象 | 多半是 | 怎么修 |
|---|---|---|
| 只有最左（或最右）一片亮 | 级联顺序搞反了 | 数据是从 DIN 那端进去的，先确认哪端是 DIN；代码里 `CHIPS` 和循环方向跟着改 |
| 前两片亮、后两片黑 | 中间某一级的 DOUT→DIN 没接好 | 检查模块之间的排线/焊点 |
| 四片里有一片颜色偏暗 | 那片供电不足 | 四片共 5V 时电流较大，降低亮度试试（`BRIGHT_SCALE 60`） |

---

## 3. 图案不对（这个项目的主要战场）

### 3.1 上下颠倒（爱心变成“黑桃”）

**现象**：形状对，但是倒的。

**原因**：bit0 对应的是最下面一行，而不是最上面。

**修**：`#define FLIP_Y 1`

---

### 3.2 左右反了

**现象**：不对称的图案（比如字母）左右镜像。

**原因**：数据从点阵的右端进去，整幅画面被镜像了。

**修**：`#define FLIP_X 1`

> 注意：**对称图案（爱心）左右反了看不出来**。所以别用爱心测左右——用字母或 L。

---

### 3.3 图案被“切成两半”，左右两半形状还不一样 ⭐

**这是这个项目最难的一个 bug，单独讲。**

**现象**：

- 点亮一颗爱心，看到的是**两块互不相干的亮斑**
- 左半边“上宽下窄”，右半边“上窄下宽”
- 两块之间有一道缝，怎么看都不像一颗心

**为什么难**：它不像“全黑”那么明显，你会怀疑是图案画错了、位置写错了、甚至模块坏了。

**真正原因**：这块 8×32 板是**转置接法**——每片的 8 个寄存器对应 8 **行**，不是 8 列。你按“列”写进去，硬件按“行”读出来，每一片都把图像**转置**了一遍。

**怎么确认**（关键一步）：

把“代码应该画出来的图案”和“实际拍到的图案”逐颗对比。最直观的办法是把期望图案**叠在照片上**：

```python
# 伪代码
expected[r][c] = HEART[r][c] == '#'
actual[r][c]   = 照片里第 r 行第 c 列亮不亮
print("不一致的灯数：", 差异数)
```

如果中心区域大面积吻合、边缘零星不符 → 映射是对的，只是整体被变换过。
如果**左右两半的形状互为“反方向”** → 转置。

**修法**：发数据前先转置。

```cpp
for (uint8_t r = 0; r < 8; r++) {
  uint8_t bits = 0;
  for (uint8_t b = 0; b < 8; b++)
    if (canvas[c * 8 + b] & (1 << r)) bits |= (1 << b);
  maxWrite(c, r + 1, bits);
}
```

**为什么之前的测试没发现**：

我用了 L 形自检码（一整列 + 一整行）。**L 转置之后还是 L**——整行还是整行、整列还是整列，形状一模一样。所以 L 测试对这个 bug 完全免疫。

> 教训：测试图案必须能区分你想测的所有情况。整行整列测不出转置，得用“不满行不满列”的图形（爱心、字母、三角形）。

---

### 3.4 图案整体偏左/偏右

**现象**：形状对，但位置不在中间。

**原因**：字符画每行的左右空格数量不对称。

**修**：数一下每行是不是 32 个字符。32 列、爱心 12 列宽，两边应该各 10 个空格：

```
"..........############.........."
 ↑10 个空格   ↑12 个'#'    ↑10 个空格
```

> 小技巧：把每行粘贴到编辑器里，看行尾列号是不是 32。差一个字符，图案就偏一格。

---

### 3.5 图案缺一块 / 有几颗灯永远不亮

**现象**：固定位置的那几颗灯从来不亮。

**原因**：可能是那颗 LED 坏了，也可能是某个寄存器地址算错。

**怎么区分**：写一个“全亮”测试（`memset(canvas, 0xFF, 32)`）。全亮时如果那颗还是不亮 → 硬件坏了；全亮时亮、图案里不亮 → 软件问题。

## 4. 上传失败

| 报错 / 现象 | 多半是 | 怎么修 |
|---|---|---|
| `avrdude: stk500_recv(): programmer is not responding` | 端口选错，或板子没复位 | 换端口；按一下板子上的 RESET 再上传 |
| `avrdude: ser_open(): can't open device` | 串口被占用 | 关掉串口监视器 / 其他占用串口的软件 |
| 编译报 `xxx was not declared` | 函数写在调用之后，且没有声明 | 把函数挪到前面，或在文件顶部加函数声明 |
| 编译报 `expected ';' before ...` | 上一行少分号 | 看报错行的**上一行**，通常是那里漏了 `;` |
| 上传成功但没反应 | 板子没复位 / 上传到了别的板子 | 按 RESET；确认 IDE 里选的端口就是这块板 |

## 5. 其他

| 现象 | 原因 | 修 |
|---|---|---|
| 很暗、闪烁、板子反复重启 | USB 供电不够（4 片全亮约 300–500 mA） | 降低亮度；换 5V 2A 电源；别用 USB hub |
| 亮度忽明忽暗但不是程序效果 | 电源纹波 / 接触不良 | 检查 GND 是否牢靠 |
| 拍照片永远拍不出效果 | 手机自动曝光被红光带偏 | 拍的时候手动降曝光，或者等“安静”那一帧 |

## 6. 通用排查原则（以后做别的项目也能用）

1. **先怀疑线，再怀疑代码**。50% 的“不工作”是线没插好。
2. **一次只改一个变量**。改完立刻验证，别攒着。
3. **让程序自己报告状态**。全亮自检、串口打印，比盯着板子猜快十倍。
4. **对比期望值和实际值**。把“应该怎样”和“实际怎样”并排放在一起，差异会自己跳出来。这个项目的转置 bug 就是这么找到的。
5. **测试图案要能区分所有可能**。测不出问题 ≠ 没问题（L 测不出转置）。
6. **卡住 20 分钟就换个人/换个角度**。自己盯久了会陷入固定假设——这个项目里我连续 3 次猜错方向，都是因为“认定”了某个原因。
