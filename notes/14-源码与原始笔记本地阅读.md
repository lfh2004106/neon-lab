# 为什么明明有文件，网页还显示读取失败？

原网页用 `fetch()` 去读取另一个 `.ino` 或 `.md` 文件。直接双击 HTML 时，地址是 `file://`，浏览器会限制这种读取；文件存在也不代表能被脚本读取。

现在把公开内容提前打包为一个普通 JavaScript 文件。像把要读的课文直接装进书包，打开网页时就能带着一起读。

## 内容与原文件一一对应

| 原文件 | 网站入口 |
| --- | --- |
| `heart_matrix/heart_matrix.ino` | Arduino 风格源码阅读器，支持复制和下载 |
| `notes/01-learning-notes.md` | 学习笔记：从一块点阵开始 |
| `notes/02-troubleshooting.md` | 排错笔记：灯不对的时候看这里 |
| `notes/03-project-log.md` | 我的第一个嵌入式项目：爱心点阵 |

网站项目目录里的三份 notes 已换成与用户源文件逐字节一致的原文副本。网页文章是依据它们整理的精简版，保留关键概念、排错经历、时间线和代码片段；每篇可进入原文。

原文里关于级联发送组数、转置、对角线测试及全亮自检的表述，在网页整理版中作了修订。原文件和源码未修改。前一份导入日志描述的“原笔记副本附勘误”由本次的“原文副本 + 网页整理版”取代。

## 文件怎样配合

`scripts/build-posts.mjs` 更新文章索引时，也会调用 `scripts/build-content.mjs` 生成 `site-content.js`。

内容包只读取明确列出的公开文件：资料 JSON、爱心源码和已发布文章。不会扫描 `.env`，不会收录草稿。

- 直接双击网页：从内容包读取，源码、文章、资料和日志目录可用。
- 通过 HTTP 网址访问：继续读取原始文件，服务器的 404 或错误不会被旧副本隐藏。
- AI 对话、公共留言、发布新文章：仍走原有后端，没有变成本地离线功能。

## 以后改内容

改完文章、资料收藏或项目源码后，在网站目录运行：

```powershell
node scripts/build-posts.mjs
```

把原文件、更新后的 `posts/index.json` 和生成的 `site-content.js` 一起提交。原始源码、notes 与网页精简版是不同用途的文件；更改原始笔记后，按需要同步整理文章。
